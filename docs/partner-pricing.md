# 거래처 주문 금액 연결 기준

현재 페이지는 시연 단계이며 주문·가격 API나 사내 OS와 연결하지 않는다.
공개 상품 가격을 거래처 단가로 대신 사용하지 않고, 주문 항목의 `unitPrice`는
확인 전까지 `null`로 유지한다.

- `unitPrice`: 거래처와 상품·색상·사이즈에 해당하는 원 단위 공급단가(부가세 제외).
- `quantity`: 해당 조합의 주문 수량(1~9,999장).
- `charges.vat`: 서버에서 확정한 주문 전체 부가세(원).
- `charges.shipping`: 서버에서 확정한 주문 전체 배송비(원).
- 미확인 금액은 `null` 또는 생략, 확정된 무료 배송·0원 금액만 숫자 `0`을 사용한다.

`TworldPartnerModel.lineAmount(line)`은 단가 × 수량을,
`totals(lines, charges)`는 공급가액 합계와 부가세·배송비를 포함한 총금액을 반환한다.
단가가 하나라도 미확인이면 공급가액과 총금액을 확정하지 않는다.
부가세나 배송비가 미확인이면 상품금액만 표시하고 총금액은 확인 예정으로 둔다.
세율이나 반올림 기준을 화면에서 임의로 정하지 않는다.

주문 화면의 `renderLines()`와 거래명세서는 같은 계산 함수를 사용한다.
수량 변경·상품 추가·삭제 시 기존 주문 단위 비용(`orderCharges`)을 비워
오래된 비용으로 총금액이 확정되는 것을 막는다. 거래명세서에는 항목과 비용의
사본을 담는다.

향후 OS 연동 시 인증된 거래처의 견적 응답을 현재 주문 조합과 대조하여
`unitPrice`와 `orderCharges`에 반영하고 `renderLines()`를 호출해야 한다.
수량에 따라 단가가 달라지는 정책이 있으면 단가도 무효화한 뒤 다시 견적을 받는다.
이 연결부·견적 만료/재조회 처리는 아직 구현하지 않았다.
실제 접수 시 서버가 가격·세금·배송비를 다시 검증해야 하며 브라우저의 계산값을
결제·출고 확정 근거로 사용해서는 안 된다.
